FedCode: Communication-Efficient Federated Learning via Transferring Codebooks

Exchange codebooks to make federated communication smaller

Saeed Khalilian · Vasileios Tsouvalas · Tanir Ozcelebi · Nirvana Meratnia

PaperCodePoster
OverviewMethodResultsCitation
The challenge

Sending every weight position each federated round limits communication savings even after weights have been clustered.

The contribution

FedCode usually exchanges only cluster centers in both directions, with periodic compressed-weight transfers to recalibrate client and server models.

Method overview · Based on the paper

The idea

At a glance

Even compressed model updates can overwhelm a federated learning link when the full update is sent every round. FedCode exchanges compact codebooks of weight-cluster centers in most rounds, periodically transferring compressed weights to realign client and server models. Clients cluster all model weights together in a model-wide step.

  • Avoiding repeated weight-position transmission can save more communication than clustering alone.
  • Periodic calibration is essential: relying exclusively on codebooks can greatly reduce accuracy.
  • Upstream-only savings can exaggerate practical benefit; inspect the joint upstream-plus-downstream metric.

Read the abstract

Federated Learning (FL) is a distributed machine learning paradigm that enables learning models from decentralized local data. While FL offers appealing properties for clients' data privacy, it imposes high communication burdens for exchanging model weights between a server and the clients. Existing approaches rely on model compression techniques, such as pruning and weight clustering to tackle this. However, transmitting the entire set of weight updates at each federated round, even in a compressed format, limits the potential for a substantial reduction in communication volume. We propose FedCode where clients transmit only codebooks, i.e., the cluster centers of updated model weight values. To ensure a smooth learning curve and proper calibration of clusters between the server and the clients, FedCode periodically transfers model weights after multiple rounds of solely communicating codebooks. This results in a significant reduction in communication volume between clients and the server in both directions, without imposing significant computational overhead on the clients or leading to major performance degradation of the models. We evaluate the effectiveness of FedCode using various publicly available datasets with ResNet-20 and MobileNet backbone model architectures. Our evaluations demonstrate a 12.2-fold data transmission reduction on average while maintaining a comparable model performance with an average accuracy loss of 1.3% compared to FedAvg. Further validation of FedCode performance under non-IID data distributions showcased an average accuracy loss of 2.0% compared to FedAvg while achieving approximately a 12.7-fold data transmission reduction.

The approach

How it works

  1. 01

    Turn weights into a codebook

    K-means groups similar model weights and stores their cluster centers in a small codebook. The server and clients retain their own weight structure.

  2. 02

    Exchange centers in both directions

    The server sends a codebook for clients to update their weights using binary search. After local training, clients return codebooks; the server concatenates their centers and maps its weights to the nearest centers.

  3. 03

    Recalibrate periodically

    Selected rounds also transmit compressed weight matrices with the codebook. Client-side calibration realigns local assignments; server-side calibration reconstructs client models and applies FedAvg.

Experiments & evidence

What the results show

Compare joint communication savings with accuracy loss; very large compression ratios can hide severe utility degradation.

Data and models
CIFAR-10/100 with ResNet-20 and MobileNet v2; 12-class SpeechCommands v2 with YAMNet.
Federated setting
10 clients; 10% or 100% participation; Dirichlet concentrations 10 and 0.1; Adam, four local epochs, batch size 128.
Compared with
FedAvg, FedAvg with weight clustering, and FedZip; MUCSC could not be reproduced from its reported clustering details.
Measured scope
Test accuracy, communication volume/DTR, and bits per parameter; computational complexity is analyzed, without a measured edge-device energy or latency benchmark.

Scope & limitations

  • This page uses the November 2023 arXiv v1 preprint, whose summary statistics differ from the IEEE EDGE 2024 published version. Results from those versions are not combined.
  • Codebook size, calibration frequency, participation, and training duration jointly affect the results. Savings from a selected setting are not a universal compression guarantee.
  • Reported tables contain no run-to-run uncertainty. Model- and distribution-specific settings differ, including up to 2,000 rounds in the MobileNet appendix.
  • FedCode is a communication method. Keeping raw data local and compressing updates do not provide a demonstrated privacy guarantee against inference or malicious clients.
